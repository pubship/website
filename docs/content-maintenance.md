# Content maintenance

For each PubShip feature, authentication, data-handling or release change, review this site with `pubship/pubship` in the same delivery cycle. Link the issue and PR, or record the exact claims inspected if no copy change is necessary.

Use only evidence-backed counts from the generated method catalog. Keep local use first. No project-run Google service, public OAuth onboarding or customer enrollment claims. A candidate is not published merely because code exists. Update publication wording after PyPI and registry verification.

Check all pages at mobile and desktop widths, keyboard behavior, accessibility, reduced motion and links. Keep footer non-affiliation and trademark statements on every page. Maintain sitemap.xml, robots.txt, llms.txt and security.txt. Regenerate social.png after changing social.svg. Keep private: true in package.json.
